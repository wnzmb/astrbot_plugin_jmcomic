# 插件功能与上游 jmcomic 能力对比（v0.7.10 vs jmcomic 2.7.10）

> 对比基线：本插件 `0.7.10`（`metadata.yaml`）对 jmcomic **2.7.10**（2026-10-22）。
> 依据：插件源码 `core/ services/ handlers/ ui/ main.py`、`_conf_schema.json`、上游源码 `src/jmcomic`（`jm_client_interface.py` / `jm_entity.py` / `jm_downloader.py` / `jm_plugin.py` / `jm_feature.py` / `jm_runtime.py` / `jm_task_context.py`）、`docs/jmcomic-CHANGELOG.md`。
> 本文只做对比与评估，不含代码改动；实际改造记录见 `docs/开发文档与修复日志.md`。

---

## 1. 结论先行

1. **定位不同**：上游是「下载引擎 + 命令行 + 可插拔扩展」，插件是「IM 场景的机器人产品」。上游提供能力原语，插件负责会话、权限、分页、消息预算、文件投递、缓存治理。因此「插件没用到上游某功能」多数是**设计取舍**，不是缺陷。
2. **当前最需要处理的不是新功能，而是 2.7.10 的行为变更**：`get_album_detail` 默认 `allow_redirect=True` 会把章节 ID 静默重定向到父漫画，插件 `jmv`/`jmlist`/`jmc`/`jmsub` 依赖的「章节 ID → 提示用户」路径会失效，属于 **P0 兼容性风险**（见 §5）。
3. **值得接入的上游新能力只有 3 个**：`DownloadControl`（协作式取消，替代 `task.cancel()`）、`DownloadManifest`（精确产物清单，替代目录扫描对账）、`series_id`/`allow_redirect`（本子归属识别）。其余（Runtime、BatchResult、JTC、Feature 链、加密打包、长图、邮件、Calibre）**不建议接入**。
4. **不建议引入上游任何 `JmOptionPlugin` 新增项**。现有 `advanced_retry` + `login` 已覆盖插件场景；`zip`/`img2pdf`/`long_img` 会与自研打包、审核与体积策略冲突。
5. `docs/` 目录存在明显的「历史快照 vs 现行文档」混杂问题，`REFACTOR_PLAN.md`（1064 行）已完全过时，应归档而非继续维护（见 §7）。

## 2. 架构对比

| 维度 | 上游 jmcomic 2.7.10 | 本插件 0.7.10 |
|---|---|---|
| 分层 | `api`（顶层函数）→ `JmOption`（配置）→ `client`（HTTP/HTML）→ `downloader`（执行）→ `plugin`/`feature`（扩展点） | `main.py`（组合根 + 命令包装）→ `handlers/`（命令编排）→ `services/`（业务能力）→ `core/`（config/client/state/downloader/models/parsing）+ `ui/`（纯文案） |
| 入口 | CLI `jmcomic` / Python API | AstrBot `Star` 插件，26 个 `@filter.command` + 1 个 `@filter.regex` |
| 并发模型 | 同步多线程 Executor + 可选异步客户端；2.7.9 起有 `JmRuntime` 统一管理层级线程池 | 同步 client + `asyncio.to_thread`；整本 `jmcomic.download_album_async`，单章 `download_photo_async`；插件自己管理 asyncio task |
| 取消 | 2.7.9 起 `DownloadControl`（线程安全、幂等、协作式） | `asyncio.Task.cancel()` + 外层捕获 `CancelledError` |
| 产物对账 | `DownloadManifest`（图片清单 + 导出文件字典 + 顶层耗时） | 目录扫描 + `page_arr` 页数比对 + `album.page_count` 对账 |
| 扩展方式 | `JmOption.plugins`（`after_init` / `before_album` / `after_album` / `after_photo` 等钩子）+ `Feature` 链 | 插件自身 service 组合，不依赖上游钩子 |
| 配置 | `option.yml` / dict | AstrBot `_conf_schema.json`（45 项），运行时 `_build_option()` 生成 option dict |
| 交付形态 | 本地目录 / 压缩包 / PDF | QQ 群/私聊消息 + 文件，带配额、分页、二次确认、消息预算 |
| 可测试性 | 无内置测试框架，靠 CLI 实跑 | 30 个 `unittest`，`ruff check .` + `compileall` + schema JSON 校验 |

**关键差异**：上游 2.7.9 之后把「调度/取消/结果」抽象成 Runtime / DownloadControl / BatchResult，是**面向长任务与批量任务的引擎化**；插件是**面向单次交互的会话化**。两者抽象层级不同，硬套上游新抽象收益有限。

## 5. 2.7.10 行为变更适配状态（P0）

### 5.1 变更内容

`get_album_detail(album_id, allow_redirect=True)`：当传入的是多章本子的子章节 ID 时，打印 `api.album_redirect` 日志并**自动重定向**到父本子。

实测（本地 2.7.10 源码 + 真实 API）：

| 请求 | `allow_redirect` | 返回 `album_id` | `series_id` | `name` | `authors` | 首项 `photo_id` |
|---|---|---|---|---|---|---|
| `43164` | `True` | `43164` | `43164` | 正常标题 | `['甘诘留太']` | `43164` |
| `275013` | `True` | **`43164`** | `43164` | 正常标题（父本） | `['甘诘留太']` | `43164` |
| `275013` | `False` | `275013` | `43164` | `奈奈与薰的SM日记_第90话.zip` | `['filename']` | `43164` |

### 5.2 影响面

| 位置 | 现状 | 2.7.10 后果 |
|---|---|---|
| `handlers/album.py` `/jmv` | `get_album_detail(album_id)` → `looks_like_chapter_album()` 判定 → 提示「这是章节 ID，父本是 JMxxx」 | 重定向后返回父本，`looks_like_chapter_album()` 为 `False`，**直接展示父本详情**，用户以为查的是章节 |
| `handlers/album.py` `/jmlist` | 同上 | 同上，展示父本话列表 |
| `handlers/library.py` `/jmc` | 同上 | 同上，展示父本评论 |
| `handlers/subscribe.py` `/jmsub` | 同上 | 同上，可能把章节 ID 当父本订阅成功 |
| `services/selection.py` `resolve_target()` | 先 `get_photo_detail` 判章节；失败才 `get_album_detail` | 章节探测优先，**大部分场景不受影响**；但 `MissingAlbumPhotoException` 兜底分支会拿到父本，`kind` 判为 `album`，`id` 仍是章节 ID → 后续 `download_album(章节ID)` 可能整本下载 |
| `services/catalog.py` `resolve_chapter_album_parent()` | 依赖畸形 album 首项 | 重定向后拿不到畸形 album，**该方法退化为 `get_photo_detail` 兜底**（仍可用，但多一次请求） |

### 5.3 建议修复（P0）

统一包一层兼容函数，放在 `services/catalog.py`：

```python
def get_album_detail_compat(client, album_id):
    """2.7.10 起禁用自动重定向，保留章节 ID 的畸形 album 识别路径。"""
    try:
        return client.get_album_detail(album_id, allow_redirect=False)
    except TypeError:  # 旧版或 HTML 客户端无该参数
        return client.get_album_detail(album_id)
```

调用点改为 `asyncio.to_thread(self.catalog.get_album_detail_compat, client, album_id)`：

- `handlers/album.py`（2 处）
- `handlers/library.py`（1 处）
- `handlers/subscribe.py`（1 处）
- `services/selection.py`（2 处兜底分支）

**注意**：HTML 客户端 `get_album_detail` 无 `allow_redirect` 参数，`TypeError` 回退可保证 API/HTML 行为一致（HTML 本身不重定向，畸形 album 识别路径天然可用）。

### 5.4 验证方式

- `unittest`：mock client，断言 `get_album_detail_compat` 优先传 `allow_redirect=False`，`TypeError` 时回退。
- 真实环境：`/jmv 275013`、`/jmlist 275013`、`/jmc 275013`、`/jmsub 275013` 应提示「章节 ID，父本 JM43164」；`/jm 275013` 应只下该话。

## 6. 上游新能力采用建议

### 6.1 建议采用

| 能力 | 优先级 | 收益 | 成本 | 说明 |
|---|---|---|---|---|
| `allow_redirect=False` 兼容包装 | **P0** | 修复 4 个命令的语义回退 | 低（1 个函数 + 6 处调用） | 见 §5 |
| `series_id` 用于章节归属判定 | P1 | 比「畸形 album 特征」更可靠，可去掉 `authors == 'filename'` 这类启发式 | 低 | `series_id not in ('0','',album_id)` 即章节 |
| `DownloadControl` 协作式取消 | P1 | 取消更干净，避免半成品与线程泄漏；`/jmstop` 语义更准 | 中（需把 control 传入 downloader 上下文，改造 `services/download.py` 与 `handlers/download.py`） | 当前 `task.cancel()` 对 `to_thread` 内的同步下载无效，只能等线程结束 |
| `DownloadManifest` 产物清单 | P2 | 精确知道本次产出哪些文件，替代目录扫描对账 | 中 | 与现有缓存对账逻辑有重叠，收益中等 |
| `DAILY_ALREADY_CHECKED_IN_KEYWORDS` | P2 | 上游文案变化时签到判重不失效 | 低 | 可读取该字段做关键字合并 |

### 6.2 不建议采用

| 能力 | 原因 |
|---|---|
| `JmRuntime` / `JmSyncRuntime` / `JmAsyncRuntime` | 插件用 `asyncio.to_thread` + 配置化线程数已够；引入共享池会与 AstrBot 事件循环生命周期耦合，易泄漏 |
| `BatchResult` | 插件分批串行是为消息预算与分册服务，批量 API 反而打乱顺序与配额 |
| `JTC` | 纯门面，无实际收益 |
| `Feature.export_pdf` / `export_zip` | 自研打包能力更强（封面页、三级回退、文档属性、分册） |
| `zip` 插件加密 | 破坏在线解压、审核与体积策略 |
| `long_img` | 体积与审核风险，已移除 |
| `img2pdf` 插件 | 自研三级回退更稳 |
| `find_update` 插件 | 自研订阅已覆盖且更完整 |
| `download_progress` | CLI 专用 |
| `send_qq_email` / `calibre_metadata` / `jm_server` / `auto_set_browser_cookies` | 与 IM 插件场景无关 |
| 新增 `image_suffix_filter` / `delete_duplicated_files` / `replace_path_string` | 与现有命名/清理策略冲突 |

## 8. 功能更新建议（按优先级）

### P0：必须做（兼容性）

1. **`allow_redirect=False` 兼容包装**（§5.3）。不做会导致 `/jmv`、`/jmlist`、`/jmc`、`/jmsub` 对章节 ID 的提示语义失效，用户会被静默导向父本。
2. **补 `unittest`**：mock `get_album_detail` 的 `allow_redirect` 参数传递与 `TypeError` 回退。

### P1：值得做（可靠性/体验）

3. **`/jmstop` 改用 `DownloadControl`**：当前 `task.cancel()` 无法中断 `asyncio.to_thread` 内的同步下载，线程会继续跑到结束，浪费流量且可能留下半成品。改造点：`services/download.py` 创建 `DownloadControl` 放入 `jm_task_context`，`handlers/download.py` 调 `control.cancel()`。
4. **用 `series_id` 替代畸形 album 启发式**：`looks_like_chapter_album()` 目前依赖 `authors/tags == 'filename'` 与首项 `photo_id`，属于对上游实现细节的猜测；`series_id` 是 2.7.10 的正式字段，更稳。可保留旧判断作兜底。
5. **`/jmv` 展示收藏/点赞状态**：实体已有 `is_favorite` / `liked`，加两行文案即可，对号主有用。
6. **订阅判重读取 `DAILY_ALREADY_CHECKED_IN_KEYWORDS`**：低成本，避免上游文案调整导致签到误报。

### P2：可选（有收益但优先级低）

7. **`DownloadManifest` 产物清单**：替换目录扫描对账，减少「半成品缓存」误判；但现有 `page_arr` + `page_count` 对账已能覆盖主要场景。
8. **章节列表展示 `page_number`**：上游搜索结果带页码，插件目前只用自有分页；收益仅在「跳页」场景。
9. **`check_photo` 单章完整性校验**：可替代部分自研校验，但需确认其对页段下载（`-c 5:201-`）的兼容性，风险大于收益，暂缓。

### 不建议做

10. **引入上游 `zip` / `img2pdf` / `long_img` / `Feature` 打包链**：与自研分册、封面页、审核策略冲突。
11. **引入 `JmRuntime` 共享线程池**：与 AstrBot 事件循环生命周期耦合，泄漏风险高。
12. **引入 `BatchResult` 批量下载**：打乱消息预算与分册顺序。
13. **新增「收藏夹导出 CSV/JSON 以外的格式」**：`/jmfav export` 已覆盖，边际收益低。
14. **新增「自动追更 + 自动下载」**：订阅已能推送，自动下载会放大配额与审核风险。
