# AstrBot JMComic 插件

漫画站 QQ 机器人插件，基于 [jmcomic](https://github.com/hect0x7/JMComic-Crawler-Python) 库开发，支持搜索、查详情、评论翻页、下载 PDF/ZIP、批量下载、按话选择、下载进度查询、列表/搜索/评论/历史翻页、请求级域名重试、HTTP/SOCKS5 代理、每日签到、收藏夹管理与 CSV 导出、订阅更新推送、群白名单、排行榜、随机抽漫、下载历史、敏感词自动转拼音、简繁自动转换、缓存元数据与标题打包等功能，所有参数均可在配置页自定义。

---

## 安装

1. 在 AstrBot 管理面板 → 插件 → 安装插件 → 从链接安装
2. 填入仓库地址：`https://github.com/wnzmb/astrbot_plugin_jmcomic`
3. 安装完成后，点击插件齿轮图标，填写配置：
   - 客户端类型：api（推荐，功能全）或 html（支持分类筛选）
   - 用户名：你的站点账号（可选，签到/收藏需要）
   - 密码：你的站点密码（可选）
   - 镜像站域名：你能访问的镜像站（支持多个，用英文逗号分隔，自动切换可用的）
   - 号主ID `owner_ids`：JM 账号号主的发送者 ID，多个用英文逗号分隔；签到、收藏、用户信息只允许号主使用。QQ 官方机器人填 openid，可先发 `/jmwhoami` 查看
   - 群聊白名单 `enabled_groups`：只允许这些群号使用插件，英文逗号分隔；留空表示不限制。关闭 `allow_group` 时所有群禁用，私聊不受影响
   - 下载并发数：根据自己网络调整
   - 分页每页条数 `per_page`：搜索、`jmlist`、`jmhis` 统一使用，默认 10 条，可改 5-20
   - jms 纯数字查详情 `numeric_search_as_album`：默认开启，`/jms 123456` 直接显示漫画详情；关闭后按普通搜索词处理
   - 订阅检查间隔 `subscribe_interval`：默认 3600 秒（1 小时）；填 `0` 关闭后台检查，只保留 `/jmsub` 的订阅增删
   - 文件发送限额：默认每日 0、每小时 0（不限制）；QQ 官方机器人通常限制每日 100 个、每小时 50 个，可按需自行填写。插件会本地计数并在超限时提示
   - ZIP 合并话数 `zip_group_size`：默认 5，表示最多 5 话合并一个 ZIP；填 1 表示每话一个
   - ZIP 每册页数上限 `zip_page_limit`：默认 300 页，单话超限时按页切分；填 `0` 表示只按话数合并
   - PDF 每册页数上限 `pdf_page_limit`：默认 200 页，整话优先，单话超限时按页切分；每个分册都带漫画信息页
   - 翻页会话有效期 `page_turn_timeout`：默认 60 秒；列表、搜索、评论、历史、排行榜发出后，在此时间内发送“下一页/下页”或 `/jmnext` 可自动翻页；填 `0` 关闭自动翻页会话
   - 话页数后台预取 `page_prefetch_pages`：默认 2 页，范围 0-5；`jmv`/`jmlist` 当前页显示后，后台继续预取之后 N 页的话页数，`0` 关闭
   - 代理 `use_proxy` / `proxy_url`：默认关闭直连；开启后填写 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`
   - 下载重试无需配置：同步请求走域名轮询，整本下载再保留 3 次外层任务重试，已下载图片自动复用缓存
   - 下载历史保留条数 `history_max`：默认 0，填 `0` 表示保留所有历史
   - 自定义敏感词 `custom_sensitive`：每行 `原文=替换拼音`，长词优先匹配；默认内置常用词，可自行增删，留空则只保留内置的 `X交`/`X乳` 规则

> 配置页使用“短标题 + 下方详细说明”的布局，数值项可以直接拖滑杆；说明文字不会再挤在标题里被截断。

### 依赖要求

- **jmcomic >= 2.7.9**（推荐，完整功能；`requirements.txt` 会自动安装/升级）
- **img2pdf >= 0.5.1 / reportlab >= 4.0.0**（PDF 合成优先 img2pdf，失败时 reportlab 逐页写入，最后回退 Pillow；用于降低大文件内存占用）
- **PySocks >= 1.7.1**（SOCKS5 代理；不配置代理时不影响普通下载）
- **pypinyin / zhconv / Pillow / PyYAML**（敏感词转拼音、简繁转换、PDF 回退与配置读取，随 `requirements.txt` 安装）
- 版本能力说明：评论翻页需 2.7.3+，下载耗时统计需 2.7.4+，删除收藏需 2.7.6+，每日签到需 2.7.7+
- 如版本过低，在 AstrBot 后端 Python 环境执行：`pip install -U -r requirements.txt`

### 客户端类型说明

| 类型 | 优势 | 限制 |
|---|---|---|
| **api**（推荐） | 收藏添加/删除、评论翻页、每日签到、域名自动更新 | 不支持分类筛选 category |
| **html** | 支持分类筛选 category/sub_category | 收藏添加报错、评论最多10条不翻页、总数解析不出 |

> 需要收藏/签到/评论翻页选 api；需要按分类浏览选 html。切换后需重启插件生效。

### 🧹 维护

| 指令 | 用法 | 功能 |
|---|---|---|
| `/jmdisk` | `/jmdisk` | 查看下载缓存、ZIP/CSV 临时目录占用（管理员/号主） |
| `/jmclean` | `/jmclean [天数\|all]` | 清理图片缓存，保留 `metadata.json`；30 秒内二次确认 |
| `/jmtest` | `/jmtest` | 诊断配置域名、代理和登录态（管理员/号主） |

> **PDF/ZIP 合并规则已分开**：PDF 按 `pdf_page_limit` 页数分册，**整话优先，只有单话超过上限时才按页切分**（例如 500 页切成 200+200+100 三册）；显式页段只打包所选页段。ZIP 同时受 `zip_group_size` 话数和 `zip_page_limit` 页数约束，先到哪个就封口，单话超限也会按页切分。命令里的 `-g` 已取消，统一在插件配置页修改，批量或 `-c` 选话同样生效。

> **下载重试**：同步请求使用 jmcomic 的请求级域名轮询，单次请求会按历史失败次数排序域名并自动切换；整本下载仍保留 3 次外层任务重试，已下载图片会复用缓存，不会从头重下。
>
> **缓存复用**：整本、选话、批量下载都会先查图片缓存；命中时直接复用，不重复下载。为压缩消息数量，不再单独发送缓存命中提示。
>
> **停止下载**：`/jmstop` 只会取消当前用户自己的下载任务，不影响其他用户；下载过程中可随时发送 `/jmnow` 查看进度。AstrBot 管理员可用 `/jmnow -all` 查看所有用户、`/jmstop -all` 停止所有用户（`all` 不带横线也可，与 `/jmhis -all` 一致）。

> **为什么删除 `/jmlong`**：长图 PNG 体积比 PDF/ZIP 大很多，传输慢且容易触发平台限制；如果 AstrBot 开启了图片压缩，长图还会被压糊甚至直接损坏。需要单话看图请用 `/jm <章节id>`。

> **QQ 文件限额**：QQ 官方机器人默认每日最多 100 个文件、每小时最多 50 个，可在配置页调整；两项都填 `0` 表示不限制。PDF 按页数分册、ZIP 按话数 + 页数合并，都是为了减少文件数；达到限额后插件会停止并提示剩余数量，已下载的图片会保留缓存，稍后可用 `-c` 继续。页段续传会精确到页，例如 `/jm 1215253 -c 5:201-` 不会重发第 5 话前 200 页。v0.7.8 起下载过程只保留开始状态、文件消息和必要的失败/限额提示；收尾汇总在预算允许时合并为一条，预算不足时省略。逐章进度、缓存、开始打包和打包完成消息不再单独发送。

**文件命名规则**：

| 输出 | 文件名 |
|---|---|
| 单话 PDF/ZIP | `JM{漫画id}_P{位置号}.pdf/.zip` |
| 单话页段 PDF/ZIP | `JM{漫画id}_P036_p001-010.pdf/.zip` |
| 同话多个不连续页段 | `JM{漫画id}_P036_p001-005_p010-015.pdf/.zip` |
| 多话合并 PDF/ZIP | `JM{漫画id}_P031-P035.pdf/.zip` |
| 多话 + 单页段 | `JM{漫画id}_P031-P035_p201-400.pdf/.zip` |
| 多话 + 多页段 | `JM{漫画id}_P031-P035_P040p201-400.pdf/.zip` |

`P` 大写只表示网站话序号（该话在章节列表中的位置，从 1 起，3 位补零），`p` 小写只表示页码。下载文件统一以漫画 ID 开头，不再使用章节 ID 或站点标题作为文件名。同一话的多个不连续页段会分别保留（如 `31:1-5,31:10-15` 不会带上第 6-9 页）；连续话用 `P031-P035`，非连续话用 `P031,P035,P040`，避免把只含 3 话的文件标成 `P031-P040`。ZIP 内每个话目录名统一为 `P{章节id}_第N话`，页段目录追加 `_p起始-结束`，单话 ZIP 也会包一层目录。缓存目录为 `JM{漫画id}/P{章节id}_第N话/图片`，标题保存在同目录的 `metadata.json`。

打包时会把标题一起带上：ZIP 根目录附 `漫画信息.txt`；PDF 写入文档属性，并给**每个分册**都加一张漫画信息页。信息页只用于展示，不计入 `pdf_page_limit` 的图片页数。找不到中文字体时会跳过信息页，但 PDF 文档属性仍会写入。

## 排序参数

搜索类指令都支持排序参数，加在最后面就行。

| 参数 | 说明 |
|---|---|
| `mr` | 最新发布（默认） |
| `mv` | 最多浏览 |
| `mp` | 最多页数 |
| `tf` | 最多收藏 |
| `tr` | 评分最高 |
| `md` | 最多评论 |

**示例**：
```
/jms jk mv        # 按最多浏览排序
/jms jk 2 tf      # 第2页 + 最多收藏
/jma MrBlack mv   # 作者搜索 + 最多浏览
```

💡 搜索小提示：建议只打前几个关键词，打全容易因为网站标题简繁混杂漏结果。

搜索结果现在会显示总结果数，例如 `第1页，第1-10条，共 123 条`。

## /jmv 详情精简选项

可以加参数去掉详情中的某些字段：

| 参数 | 说明 |
|---|---|
| `-author` | 去掉作者行 |
| `-work` | 去掉作品行 |
| `-role` | 去掉人物行（查询提示显示“不带角色”） |
| `-tag` | 去掉标签行 |
| `-pic` | 不发送封面（默认转为 PDF 文件发送，避免 QQ 图片审核） |

> v0.7.1 起详情不再显示简介和相关推荐，`-desc`、`-related` 选项已移除。v0.7.2 起无法识别的选项会直接提示，不会静默忽略。v0.7.3 起下载支持页段续传（`-c 5:201-`）。v0.7.4 起文件名不再拼接漫画标题，并修复长标题路径、批量重复文件、部分缓存等问题。v0.7.5 起缓存目录只保留 ID，标题写入 `metadata.json`，并随 ZIP/PDF 一起打包。v0.7.6 起同一话的多个不连续页段会分别保留，并修复章节ID提示缺少父漫画ID。v0.7.7 起整本下载进度按 10% 步进 + 60 秒心跳推送，新增 HTTP/SOCKS5 代理与请求级域名重试。v0.7.8 起新增群白名单、`jms` 纯数字查详情、收藏夹 CSV 导出（30 秒二次确认）和 `/jmsub` 订阅更新推送；分册命名统一为 `JM{漫画id}_P{话序号}`，每个 PDF 分册都带信息页，缓存/ZIP 目录改为 `P{章节id}_第N话`，`jmlist`/`jmhis` 统一走 `per_page`。同一版本后续更新：移除可见进度条，新增 `/jmnow` 查询当前下载进度；`/jm`、`/jmzip` 压缩状态消息；`/jmv`、`/jmlist` 的话列表追加每话页数；新增 `/jmnext` 和“下一页/下页”自动翻页（`page_turn_timeout` 秒内有效）；`/jmnow`、`/jmstop` 支持管理员 `-all` 查看/停止所有用户下载。

**示例**：
```
/jmv 123456              # 正常发全部
/jmv 123456 -role        # 去掉人物
/jmv 123456 -work        # 去掉作品
/jmv 123456 -author      # 去掉作者
/jmv 123456 -role -work  # 去掉人物和作品
/jmv 123456 -pic         # 不发送封面
```

## 分页说明

- 默认每页显示 10 条结果（配置项 `per_page` 可调，范围 5-20）
- 第 2 页 = 第 11-20 条
- 第 3 页 = 第 21-30 条
- 以此类推

回复最后会自动带下一页的指令，直接复制发送就行；也可以在 `page_turn_timeout` 秒内直接发送“下一页/下页”，或使用 `/jmnext`。翻页会话按用户和会话隔离，超时后需重新执行原列表命令。

## 其他说明

- **数据存储**：下载缓存、历史记录和文件限额状态保存在 `data/plugin_data/astrbot_plugin_jmcomic/`；插件配置由 AstrBot 保存（通常为 `data/config/astrbot_plugin_jmcomic_config.json`），插件更新不会丢失
- **缓存目录**：v0.7.8 起按 `JM{漫画id}/P{章节id}_第N话/` 命名，标题、作者、标签和话列表写入 `metadata.json`，从根源避免长标题导致 Windows 路径超限；旧版 `P{章节id}` 目录会在下次读取时自动迁移。升级后若旧缓存不完整，可删除对应 `JM{漫画id}` 目录后重下
- **话列表页数**：`/album` 接口不返回每话页数；`/jmv` 前 10 话、`/jmlist` 当前页 10 话会并发请求章节详情补齐，首次约多 6-10 秒，结果写入该漫画的 `metadata.json`，之后直接读缓存
- **自动清理**：发送完 ZIP/PDF 后自动删除临时文件，保留原始图片缓存，下次下载同本直接复用
- **下载进度**：下载过程中直接发送 `/jmnow` 查询，不再推送进度条；返回当前用户的 JMID、已完成/总页数和未完成页数
- **下载历史**：自动记录最近下载记录，用 `/jmhis [页码]` 分页查看（每页 `per_page` 条，默认 10）；`/jmhis -all [页码]` 仅 AstrBot 管理员可用，每用户每页 10 条
- **停止下载**：`/jmstop` 取消当前发送者自己的下载任务；已经下载完成的图片缓存会保留
- **收藏夹/签到**：需要配置账号密码，且只有 `owner_ids` 中的号主可以使用
- **签到状态**：按站点签到日历统计连续天数和今日状态，API 客户端也能正确显示（数据延迟时用本机签到记录兜底）
- **评论超页**：请求页码超过总页数时直接提示"已到最后一页"，不再重复返回第一页评论
- **API 客户端**：v0.6.0 起使用移动端 API 接口，功能更全（收藏添加、评论翻页、签到等），域名自动更新
- **文件限额**：本地计数只统计本插件发送的文件，其他插件/手动发送不包含在内；如果同时使用多个机器人功能，请预留余量
